# Prototipo 1 — Comprender el problema

Este prototipo explica por qué no se debe comenzar creando tareas preventivas. Primero se identifica qué activo se analiza, qué se espera que haga, bajo qué condiciones opera y de qué formas puede dejar de cumplir su función.

### Qué verá el usuario

- Una comprobación de la información disponible.
- El contexto operacional y los límites del activo.
- Funciones redactadas con estándares medibles.
- Fallos funcionales asociados a cada función.
- Modos de fallo seleccionados desde una biblioteca contextual.
- Una primera cadena de trazabilidad.

### Mensaje principal

Un modo de fallo solo debe pasar al AMEF cuando está relacionado con una función, un fallo funcional, el contexto real y una evidencia suficiente.

### Decisiones pendientes

La fuente corporativa de activos, la profundidad exigida para el contexto, las reglas de calidad y la biblioteca definitiva de modos de fallo.
