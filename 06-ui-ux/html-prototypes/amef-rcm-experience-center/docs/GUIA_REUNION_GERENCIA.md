# Guía breve para presentar el AMEF–RCM Experience Center a gerencia

## Apertura

El objetivo de estos prototipos no es presentar una aplicación terminada. Es comprobar que el recorrido funcional que estamos construyendo mantiene una lógica coherente con lo tratado en las reuniones y que puede convertirse posteriormente en una especificación clara para IT.

## Mensaje de 30 segundos

El recorrido comienza entendiendo qué debe hacer el activo. Después analiza cómo puede fallar y qué consecuencias tendría. AMEF ayuda a evaluar y priorizar el riesgo; RCM estructura la decisión sobre la estrategia más adecuada. Solo entonces se definen tareas, frecuencias y recursos. Finalmente, todo queda trazable, aprobado y sujeto a mejora continua.

## Recorrido recomendado para la reunión

1. **Abrir el `index.html` principal.** Explicar la historia completa de cinco bloques.
2. **Entrar en el Prototipo 1.** Mostrar que todavía no existen tareas: primero se entiende el activo.
3. **Pasar al Prototipo 2.** Enseñar que el NPR no es la única regla de prioridad.
4. **Abrir el Prototipo 3.** Recorrer dos o tres preguntas del árbol RCM y modificar un escenario.
5. **Abrir el Prototipo 4.** Mostrar cómo la decisión termina en tareas concretas y recursos.
6. **Cerrar con el Prototipo 5.** Seleccionar una tarea y reconstruir su trazabilidad hacia atrás.

## Tres ideas que deben quedar claras

- No se pretende generar planes de mantenimiento por defecto.
- El sistema guía y documenta el razonamiento; no sustituye la decisión humana.
- Cada tarea del plan debe poder justificarse y revisarse con resultados reales.

## Qué pedir a los asistentes

- Validar si el orden del proceso refleja la forma correcta de trabajar.
- Señalar información que falte en alguna etapa.
- Identificar qué roles deben intervenir y aprobar.
- Confirmar cuáles de las reglas mostradas deben ser corporativas y cuáles configurables.

## Qué no conviene discutir todavía

No es necesario cerrar durante esta sesión la tecnología, el modelo de datos definitivo, la integración exacta ni el diseño visual final. Primero debe validarse el razonamiento funcional.
