## Reconciliations

1. ProposedMaintenanceTask → MaintenanceRecommendation.
2. PreventiveRecurrence → MaintenanceTriggerPolicy + TriggerRule.
3. NextDueOccurrence → ForecastOccurrence (projected) or MaintenanceDueEvent (actual).
4. CorrectiveWorkOrder → WorkOrder type/origin.
5. Frequency → Trigger Policy/Rule concern, not MaintenanceActivity primitive.

## Open contracts preventing schema freeze

1. MSL-G01 source normalization still required.
2. MSL-G02 must close MaintenanceActivity adoption semantics, JobPlan ↔ ProcedureChecklist, resources and project snapshots.
3. Triggering requires TRG-G01 to close policy lifecycle, simple/composite behavior, fixed vs last-completion, warning vs action, DueEvent idempotency and forecast/evaluation persistence.
4. Work Management still needs WM-G02/G03/G05 before WorkOrder DDL can freeze.

## Gate conclusion

The cross-domain conceptual model is coherent enough to continue safely, but not to create final SQL.

### Next real gate

**MSL-G01 — Source Normalization** remains the next evidence gate for Maintenance Engineering. Triggering should proceed to TRG-G01 only after MSL-G01 clarifies the project MaintenanceActivity/source/version contract.

This ordering prevents Trigger Policy from being designed against an unstable MaintenanceActivity contract.
