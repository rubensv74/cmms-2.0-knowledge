En la última reunión comentamos la necesidad de que la jerarquía funcional del CMMS pueda adaptarse fácilmente a cualquier tipo de instalación y a la forma en que cada cliente estructura sus activos.

A partir de ese comentario he preparado una propuesta conceptual que intenta dar respuesta a esa necesidad. El objetivo es simplificar la configuración de nuevos proyectos y reducir la fricción durante la implantación, especialmente cuando la terminología del cliente no coincide con la utilizada internamente por el CMMS.

Para facilitar su revisión he preparado una demo HTML interactiva que muestra, paso a paso, cómo podría ser este proceso de configuración.

La propuesta se basa en siete pasos:
1.	Selección de un perfil de proyecto o creación de uno nuevo. 
2.	Definición del número de niveles que utilizará la jerarquía. 
3.	Configuración de los nombres visibles para cada nivel según la terminología del cliente. 
4.	Mapeo de esos niveles con los tipos internos del CMMS. 
5.	Generación automática de una plantilla Excel adaptada al proyecto. 
6.	Construcción de la jerarquía directamente en esa plantilla. 
7.	Validación e importación al CMMS. 

La idea principal es que el usuario trabaje siempre con conceptos sencillos como Nivel 1, Nivel 2, Nivel 3..., mientras que el sistema se encargue internamente de traducir esa información al modelo de datos del CMMS. 
De esta forma se reduce la complejidad para el usuario sin modificar el funcionamiento del importador existente (versión actual de CMMS). La demo adjunta refleja este enfoque. 

Me gustaría conocer vuestra opinión sobre este planteamiento y validar si consideráis que esta dirección encaja con la visión que tenemos para CMMS 2.0.
Si el enfoque os parece adecuado, prepararía una propuesta funcional más detallada para trasladarla al equipo de IT como evolución del módulo de configuración de jerarquías.

Quedo atento a vuestros comentarios.

Muchas gracias.
